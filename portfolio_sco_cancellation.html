Oracle BI Publisher가 매달 말일 자동 발송하는 Open Sales/Transfer Order 리포트에서 30~90일째 열려 있는 SCO 라인만 골라내, Oracle Fusion Transfer Order 화면에서 직접 취소하거나 수량을 실제 처리분에 맞게 정정한다. Shipped/Received/Delivered 값이 서로 안 맞는 애매한 케이스만 사람 확인 알림으로 남긴다. Filters the monthly, auto-emailed Oracle BI Publisher Open Sales/Transfer Order report down to SCO lines that have sat open for 30–90 days, then either cancels them or corrects the requested quantity to match what's already been fulfilled — directly inside Oracle Fusion's Transfer Order screen. Only cases where Shipped/Received/Delivered disagree with each other are left as an alert for manual review.

매달 영업일 말일, Oracle BI Publisher가 자동 발송하는 Open Sales/Transfer Order 리포트에서 Ship From=KRP · Line Type=SCO · Days Open 30~90일 조건에 맞는 라인만 추려낸다. 각 Transfer Order를 Oracle Fusion에서 열어, 처리 이력이 없는 라인은 취소하고 이미 부분 처리된 라인은 Requested 수량만 실제 처리분에 맞게 정정한다.
On the last business day of each month, filters the auto-emailed Oracle BI Publisher Open Sales/Transfer Order report down to lines matching Ship From = KRP, Line Type = SCO, and a 30–90 day open window. Opens each Transfer Order in Oracle Fusion and either cancels lines with no fulfillment history, or corrects the requested quantity on lines already partially fulfilled.
Shipped/Received/Delivered가 전부 비어있으면 라인을 취소(Cancel Line), 이미 서로 같은 수량이 들어있으면 Requested를 그 수량으로 정정 — 값이 서로 다르면(부분 입고 등 애매한 상태) 자동 처리 대신 확인 알림만 발송Cancels a line outright when Shipped/Received/Delivered are all empty; corrects the Requested quantity when they already agree on a number — if they disagree (e.g. a partial receipt), skips automation and sends an alert for manual review instead
"Cancel Line" 클릭 후 뜨는 확인 다이얼로그(Yes/No)를 놓치면 화면상 아무 변화 없이 조용히 무시된 것처럼 보이는 버그를 실측으로 발견 — Yes까지 눌러야 실제 취소 대상으로 반영됨을 확인해 로직에 반영Found — by direct observation — that missing the Yes/No confirmation dialog after clicking "Cancel Line" makes the click silently appear to do nothing; fixed by explicitly confirming the dialog before treating a line as cancelled
Requested Delivery Date가 비어있으면 날짜피커의 숨은 DOM 때문에 행마다 셀 개수가 달라져, 고정 인덱스로 읽으면 엉뚱한 컬럼을 읽는 버그를 발견 — Requested 입력칸을 기준으로 그다음 세 칸을 상대 위치로 읽는 방식으로 수정Found a bug where an empty Requested Delivery Date pulls in a hidden date-picker DOM that shifts the cell count per row, so a fixed column index silently reads the wrong field — fixed by anchoring on the Requested input and reading the next three cells by relative offset
