한국(KRP) 창고에서 해외 법인(호주·홍콩·중국·일본·미국·스페인)으로 재고를 옮기는 국가간 Transfer Order(Rebalance)를, 알림 감지부터 3PL 창고 조율, Oracle 트랜잭션, 통관 Commercial Invoice 발급, 수출신고실적 기입까지 전 구간을 잇는 14단계 SOP 풀사이클을 사람 명령 없이 이어서 실행하도록 코드화했다. 3PL(용마)이 위치정보를 회신하는 순간부터는 시스템이 알아서 끝까지 처리하고, 유일하게 시스템 밖에 남는 일은 물리적 행위(FedEx/DHL 실제 픽업 예약)뿐이다. Codes the full 14-step cycle of the cross-border Transfer Order (inventory rebalance) procedure — from the first system alert, through 3PL warehouse coordination, the Oracle transaction, the customs commercial invoice, to the export declaration — to run end to end with no manual command, for stock moving from the Korea (KRP) warehouse to sister companies in Australia, Hong Kong, China, Japan, the US, and Spain. The moment the 3PL (Yongma) replies with pick-location details, the system carries the case through to completion on its own; the only work left outside the system entirely is physically booking the FedEx/DHL pickup.

Cross-Border Rebalance Export Full-Cycle
한국 창고에서 해외 법인으로 재고를 옮기는 국가간 Transfer Order(Rebalance)를, 알림 감지부터 통관 서류 발급까지 14단계 SOP 풀사이클 전체 코드화했다.
Codes the full 14-step cycle of the cross-border Transfer Order (inventory rebalance) procedure — from the first system alert through customs paperwork — for stock moving from the Korea warehouse to sister companies abroad.
SharePoint의 TO 변경 알림 메일을 감지해 대상 파트/수량을 조회하고, 3PL 창고에 위치정보를 요청하는 메일까지 자동 발송Detects SharePoint TO-change alert emails, looks up the affected part/quantity, and auto-sends the pick-location request to the 3PL warehouse
3PL 회신을 파싱하는 즉시 사람 명령 없이 바로 이어서 Oracle Fusion에 로그인해 Create Pick Wave(Transfer Order)→Confirm Pick Slips→Ship Confirm까지 실행하고 SharePoint에 결과를 다시 기입The moment the 3PL reply is parsed, logs into Oracle Fusion and drives Create Pick Wave (Transfer Order) → Confirm Pick Slips → Ship Confirm with no manual command, then writes the result back to SharePoint
수입 통관 C.I. 대사 자동화(icbl_ci_watcher.py)와 같은 Oracle 리포트·다운로드 파이프라인을 그대로 재사용해 Ship From을 반대 방향(KRP)으로 돌려 통관 Commercial Invoice를 발급Reuses the exact same Oracle report/download pipeline as the import-side C.I. reconciliation automation, just pointed the opposite way (Ship From = KRP), to issue the customs commercial invoice
PyMuPDF로 오라클이 뽑은 PDF의 빈 여백에만 국가별 담당자 정보·HTS 코드를 직접 삽입 — 서식을 다시 만들지 않아 원본 인쇄 레이아웃이 그대로 유지됨Uses PyMuPDF to insert country-specific contact details and the HTS code straight into blank space on Oracle's generated PDF — no template re-export, so the original print layout is never disturbed
실제 라이브 케이스로 14단계 전체(메일 트리거 → SharePoint → 3PL 조율 → Oracle 3단계 → 통관 인보이스 → PDF 보정 → 수출신고실적)를 실측 검증 후 코드화All 14 steps — mail trigger → SharePoint → 3PL coordination → the 3-stage Oracle transaction → customs invoice → PDF correction → export ledger — were verified against a real live case before being coded
재고를 실제로 움직이는 Oracle 트랜잭션 구간도 라이브 케이스 검증 후 무인 실행으로 전환 — 3PL 위치정보가 TO#로 명확히 매칭될 때만 자동 진행하고, 애매하게 매칭되는 케이스는 사람 확인 알림으로 남겨 안전판을 유지After live-case validation, the stage that commits real inventory movement was switched to unattended execution too — it proceeds automatically only when the 3PL's pick-location reply matches a TO# unambiguously, falling back to a human-review alert on any ambiguous match
