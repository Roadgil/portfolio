A headless Claude reads engineers' Teams requests, extracts the PO number and checks whether it was handled. It runs in shadow mode first, logging without acting.

Agent Definition

정의 파일에 들어간What the definition
규칙들file holds

ROLE · TOOLS
역할과 허용 도구를 먼저 못 박는다. 메일 검색 · Salesforce 조회 · 로컬 스크립트 실행 등 13개만 쓸 수 있다.
Role and allowed tools come first: thirteen, covering mail search, Salesforce queries and local scripts.
메인 대화에서 "파트오더 만들어줘", "승인 났어 릴리즈 해줘"라고 하면 이 에이전트로 넘어간다.
Phrases like "create the parts orders" or "approved, release them" route the work to this agent.
HARD RULES
승인 요청은 직접 지시가 있을 때만. 메일은 기본 초안. 상태 파일과 업무 엑셀은 백업 없이 고치지 않는다.
Approval only on direct instruction. Email defaults to draft. State files and working spreadsheets are never edited without a backup.
누른 버튼은 몇 시 몇 분에 눌렀는지까지 보고해, 사람이 한 번 더 누르는 중복을 막는다.
Every click is reported with its time, so nobody presses it a second time.
INCIDENT → RULE
오후 요청 2건이 빠진 날 이후, 하루 끝에 그날 요청 메일 전체와 생성된 주문을 대조하는 단계를 추가했다.
After a day when two afternoon requests were missed, an end-of-day check was added that matches every request email against the orders created.
체인 병원 지점 간 입금 오매칭이 나온 뒤에는 지점명까지 일치해야 확인으로 인정하도록 바꿨다.
After a deposit matched the wrong branch of a clinic chain, a match now requires the branch name too.
PORTABLE
에이전트 본체와 설치 가이드를 공유 폴더에 두어, 다른 PC의 Claude Code에도 같은 에이전트를 심을 수 있게 했다.
The agent definition and an install guide live in a shared folder, so the same agent can be set up in Claude Code on another PC.
가이드에는 준비물, 하루 흐름(사용자 말 → 에이전트 동작 → 도구), 알려진 함정을 표로 정리했다.
The guide tabulates prerequisites, the daily flow (what the user says, what the agent does, which tool) and known traps.

EXCEPTION → SOP

Writes exceptions back into the SOP
품목코드가 없는 부품은 기존 SOP에 절차가 없었다. 실제 건으로 입력 경로와 계정을 확정한 뒤, 같은 방식으로 자동 PO 생성까지 확인하고 SOP 문서에 예외 장으로 추가했다.
Parts with no item code had no procedure in the SOP. The entry path and account were settled on a live order, automatic PO creation was confirmed, and the result was added to the SOP as an exceptions chapter.
