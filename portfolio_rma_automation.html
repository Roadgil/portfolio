Outlook에서 "New RMA" 메일을 감지해 본문의 "Link to Parts Order"를 열고, Salesforce Classic 화면에서 Order Number와 Parts Order Lines(Disposition 포함)를 파싱한다. Disposition에 따라 Unused RMA/Defective RMA로 자동 분류하고, 정상 판정된 건은 회신을 그 자리에서 자동 발송한다.
Detects "New RMA" emails in Outlook, opens the body's "Link to Parts Order," and parses the Order Number and Parts Order Lines (including Disposition) from the Salesforce Classic screen. Auto-classifies each as Unused RMA or Defective RMA by Disposition and auto-sends the reply on confirmed cases.
Unused RMA는 Oracle Order Number가 항상 7로 시작한다는 규칙까지 교차 검증 — 10건 전수 확인, 예외 없음Cross-checks the rule that Unused RMA always has an Oracle Order Number starting with 7 — verified across all 10 test cases, no exceptions
Parts Order Lines 표에서 빈 컬럼(Work Order/Fulfillment Qty)으로 뒤 컬럼이 한 칸씩 밀리는 파싱 버그 발견·수정 — 고정 줄 수 가정 대신 Disposition 리터럴 앵커링으로 해결Found and fixed a parsing bug where empty columns (Work Order/Fulfillment Qty) shifted later columns by one — replaced a fixed-line-count assumption with anchoring on the Disposition literal instead
pick_release_watcher와 동일한 CC 고정 패턴(용마로지스)을 그대로 재사용Reuses the same fixed CC pattern (Yongma Logis) as pick_release_watcher
로그인 필요·파싱 실패·판정 이상 등 애매한 케이스만 사람 확인용 초안(Save())으로 남기고, 정상 케이스는 reply.Send()로 즉시 자동발송 — 실제 라이브 2건(RMA#00593366 Defective, RMA#00593486 Unused)을 사람이 검토해 정확함을 확인한 뒤 자동발송으로 전환Ambiguous cases (login required, parse failure, classification mismatch) fall back to a draft (Save()) for human review; confirmed cases send immediately via reply.Send() — switched to auto-send after a human verified 2 real live cases were accurate (RMA#00593366 Defective, RMA#00593486 Unused)
